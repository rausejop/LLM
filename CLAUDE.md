# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Purpose

LLM inference system (Llama 3.2) for a **hardened Windows environment where
`.exe` files cannot run, but `.dll` files can be loaded into memory**. All
inference happens by loading `llama.dll` (llama.cpp) via `ctypes`, using
**only the Python 3.12 standard library** (no pip / no external dependencies).

## Commands

```powershell
# 1. Provision: download the GGUF model and the llama.cpp DLLs.
python carga.py

# 2. Run inference (uses prompt.txt and the default model; writes output.txt).
python inferencia.py

# Verbose = maximum debug log streamed to stdout.
python inferencia.py --prompt prompt.txt --verbose

# Common options
python inferencia.py --model llama-3.2-1b-q4_k_m.gguf --prompt prompt.txt --output result.txt --n-predict 128
python inferencia.py --version    # also: --v
python inferencia.py --help

# Syntax check without running (needs neither the DLLs nor the model)
python -m py_compile carga.py inferencia.py
```

There is no test framework; the quick check is `py_compile`. A real functional
run requires having executed `carga.py` first (downloads ~800 MB model + DLLs).

## Architecture

Two independent scripts with a strict separation:

- **`carga.py`** — provisioning (network + unzip only; never runs binaries).
  Downloads the GGUF model to the root and the `.dll` files to `lib/`.
  - Model: `MODEL_URL` (Hugging Face, `medmekk/Llama-3.2-1B-Q4_K_M-GGUF`).
  - Libraries: `LLAMA_ZIP_URL` points to a **pinned build** of llama.cpp
    (`b9518`, `bin-win-cpu-x64` package). If that URL fails, it falls back to
    the GitHub `releases/latest` API (`find_llama_asset`).
  - Idempotent downloads (skips files already present; `.part` + atomic
    rename). Extracts only `.dll` files and **flattens** them into `lib/`.

- **`inferencia.py`** — loads `lib/llama.dll` with `ctypes.CDLL` and maps the
  llama.cpp C API. Flow: `backend_init -> register backends -> model_load ->
  context_new -> tokenize -> decode -> generation loop -> free`.
  - I/O: `--verbose` streams the full native debug log (and the generated
    text) to stdout via a log callback; the generated text is always written
    to the output file (`output.txt` by default, `--o`/`--output` to change).

### File layout (generated by `carga.py`; do NOT commit)

```
llama-3.2-1b-q4_k_m.gguf   # model (root)
lib/llama.dll + ggml*.dll  # native libraries
prompt.txt                 # default prompt
output.txt                 # default generation output
```

## Delicate points when editing `inferencia.py`

These details are the reason the code is shaped the way it is; preserve them:

- **By-value structs and versioning.** The `llama_*_params` structs change
  layout across llama.cpp versions. Therefore:
  - `LlamaModelParams` is an **opaque blob** (256 bytes) — defaults only.
  - `LlamaContextParams` declares only the **stable leading fields**
    (`n_ctx`, `n_batch`, `n_ubatch`, `n_seq_max`, `n_threads`,
    `n_threads_batch`) plus 512 bytes of trailing padding. On the Windows x64
    ABI large structs are passed by hidden pointer, so the extra padding is
    harmless. **Do not reorder these fields or remove the padding.**
  - `LlamaBatch` is declared field by field (stable layout).

- **Backend registration is mandatory.** Recent llama.cpp loads compute
  backends (`ggml-cpu*.dll`) as runtime plugins. `_register_backends` calls
  `ggml_backend_load_all_from_path` **before** loading the model; without it
  the model fails with "no backends are loaded". This symbol lives in
  **`ggml.dll`**, not `ggml-base.dll`.

- **Rename tolerance.** `_bind()` accepts aliases to survive API renames
  (e.g. `llama_model_load_from_file` vs `llama_load_model_from_file`,
  `llama_vocab_n_tokens` vs `llama_n_vocab`). When adding new functions, pass
  the old names as aliases.

- **Greedy sampling via logits.** The sampler API (volatile) is avoided on
  purpose: read the pointer from `llama_get_logits_ith(ctx, -1)` and take the
  `argmax` over `n_vocab`. Add temperature/top-k in Python over the logits,
  not via sampler structs.

- **Log callback lifetime.** The `LOG_CALLBACK` instances must be retained in
  `_KEPT_ALIVE`; if garbage-collected, the native library would call freed
  memory and crash.

- **DLL loading on Windows.** `llama.dll` depends on `ggml*.dll`. Order
  matters: `os.add_dll_directory(lib/)` + pre-loading `ggml-base`/`ggml`
  **before** loading `llama.dll`. The package must be **x64**.

- **Incremental UTF-8.** A multibyte character may be split across tokens;
  bytes accumulate in `pending` and are only emitted once they decode
  successfully (with `errors="replace"` only at the very end).

## Invariable constraints

- Standard library only in both scripts (no `requests`, no `numpy`, etc.).
- `inferencia.py` never spawns processes; all native code is reached via
  `ctypes`.
- Paths resolve relative to the script directory (`WORK_DIR`), not the CWD, so
  the scripts work when invoked from anywhere.
- All code, comments, and program output are in English; follow PEP 8 and the
  Google Python Style Guide (Google-style docstrings with Args/Returns/Raises).
